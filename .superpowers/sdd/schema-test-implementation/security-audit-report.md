## CRITICAL

### 1. `xlsx` (SheetJS) — Prototype Pollution + ReDoS

**File:** `node_modules/xlsx`
**CVE:** GHSA-4r6h-8v6p-xvw6 (Prototype Pollution), GHSA-5pgg-2g8v-p4x9 (ReDoS)
**Fix:** No fix available from maintainer.

The `xlsx` package is unmaintained and has known high-severity vulnerabilities. Since SANAD uses it for factory code Excel imports (`FactoryCodePage.tsx` → `factoryCode.ts`), any uploaded `.xlsx` file could trigger prototype pollution or ReDoS.

**Recommendation:** Replace `xlsx` with a maintained alternative such as `exceljs` or `xlsx-populate`. If replacement is not immediately feasible, restrict file uploads to a whitelist of trusted origins and validate file structure before parsing.

## IMPORTANT

### 2. `react-router` — Open Redirect (CVE-2025-68470)

**Package:** `react-router` 6.x / `react-router-dom` 6.x
**Severity:** Moderate (combined with other issues → Important)

React Router v6 has an open redirect via backslash in `<Link>` and `useNavigate`. The codebase uses `useNavigate()` throughout (e.g., `ProjectDetailPage.tsx:231`, `LoginPage.tsx`, etc.).

**Recommendation:** Upgrade to `react-router-dom@7.18.3+` when feasible. In the interim, validate that navigation targets are internal paths before calling `navigate()`.

### 3. `esbuild` / `vite` — Dev Server Request Smuggling

**Packages:** `esbuild <=0.24.2`, `vite <=6.4.2`
**Severity:** Moderate

esbuild's dev server allows any website to send requests and read responses. This is a development-only risk but affects any local dev sessions.

**Recommendation:** Upgrade `vite` to 8.3.0+ when the project migrates. For now, this only affects local dev environments, not production.

### 4. Missing Security Headers in Production (`vercel.json`)

**File:** `app/vercel.json`

`vercel.json` contains only rewrites — no security headers are configured for production deployments. The Vite dev server plugin (`vite.config.ts:9-18`) sets headers only during development.

**Missing headers:**
- `X-Frame-Options: DENY`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`
- `Content-Security-Policy`
- `Strict-Transport-Security` (HSTS)

**Recommendation:** Add a `headers` section to `vercel.json`:
```json
{
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "X-Frame-Options", "value": "DENY" },
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
        { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=()" },
        { "key": "Strict-Transport-Security", "value": "max-age=63072000; includeSubDomains; preload" }
      ]
    }
  ],
  "rewrites": [
    { "source": "/((?!assets/).*)", "destination": "/index.html" }
  ]
}
```

### 5. `dangerouslySetInnerHTML` — Templates Use Unescaped HTML

**Files:**
- `templates/fulla-proforma-invoice-680/Template.tsx:11`
- `templates/fulla-tax-invoice-b-680/Template.tsx:11`
- `templates/fulla-packing-list-680/Template.tsx:11`
- `templates/fulla-tax-invoice-a-680/Template.tsx:11`
- `templates/fulla-delivery-note-680/Template.tsx:11`
- `templates/fulla-commercial-invoice-680/Template.tsx:14`
- `templates/fulla-quotation-680/Template.tsx:11`

These template components render HTML strings via `dangerouslySetInnerHTML`. The HTML is generated by `template.ts` which uses `escapeHtml()` for user-supplied values (material names, customer names, notes, etc.). However, the generated HTML structure itself is not sandboxed.

**Risk level:** Moderate — input is escaped, but the pattern is inherently risky. A future change that forgets to escape would introduce XSS.

**Recommendation:** Consider using a DOMPurify sanitize step on the final HTML string before passing to `dangerouslySetInnerHTML`, or migrate to a React-based template rendering approach.

## MINOR

### 6. `@vitest/mocker` / `vitest` — Path Traversal (Dev Only)

**Package:** `@vitest/mocker <=4.1.10`
**Severity:** Moderate (dev-only)

Path traversal via redirect mock in the vitest mocker. Only affects test/dev environments.

**Recommendation:** Upgrade to vitest 5.0.0+ when feasible. No production impact.

### 7. No CSP (Content Security Policy) Header

**Files:** `vite.config.ts`, `vercel.json`

No Content-Security-Policy is defined anywhere. This means browsers won't restrict script sources, style sources, or prevent inline script execution.

**Recommendation:** Add a CSP header to `vercel.json` (see recommendation #4). Start with a report-only policy to identify violations before enforcing.

## CLEAN

### ✅ Secrets Handling

- No hardcoded API keys, passwords, or tokens found in source code (`src/`).
- `src/lib/env.ts` properly validates all environment variables with required/optional checks and URL validation.
- Server-side secrets (`SUPABASE_SERVICE_ROLE_KEY`, R2 keys) use `process.env` (not bundled into client).
- `.gitignore` excludes `.env.local`, `.env.*`, and `*.local` files.
- `.env.local` has empty placeholders for sensitive server-side values.

### ✅ RLS Policies

- All 30 tables have `ENABLE ROW LEVEL SECURITY` applied across migrations 001–013.
- Migration 013 specifically enables RLS on `permission_catalog` (was missing).
- Migration 015 adds `company_id` to `backups` table and tightens RLS with company-membership checks.
- Policies enforce company isolation via `company_memberships` joins.

### ✅ Auth Flow

- Session management via Supabase Auth with proper `onAuthStateChange` listener (`AuthContext.tsx:89-109`).
- Token refresh handled automatically by Supabase client + explicit `TOKEN_REFRESHED` event handling.
- Sign-out clears both state and Supabase session (`auth.ts:166-177`).
- Disabled users are signed out immediately on login (`auth.ts:80-83`).
- User profile fetched from DB (not JWT claims), preventing auth-metadata manipulation (`auth.ts:325-338`).
- `RequestContext` resolves user identity from session + DB, not from client-provided tokens (`api.ts:64-156`).

### ✅ Input Validation

- `validateRequiredFields()` in `api.ts:381-397` checks for missing required fields.
- `validateEmail()` and `isValidUUID()` in `api.ts:402-413`.
- `escapeHtml()` in `GlobalSearch.tsx:51-58` and `template.ts:14` properly escapes `& < > " '`.
- Base service class (`services/base.ts`) enforces `validateCreate` / `validateUpdate` abstract methods.
- `FormValidation.tsx` provides client-side form validation hooks.
- SQL injection mitigated by Supabase client parameterized queries (no raw SQL in frontend).
